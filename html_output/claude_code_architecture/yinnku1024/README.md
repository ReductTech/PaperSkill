# Claude Code 架构：一座终端里的调度所 · 交互式教程

基于 `claude-code-source-code-full` 仓库 `docs/architecture.md` 的中文交互式讲解，13 页幻灯片、5 个章节。
教程用"铁路调度所"的日常动作（信号机、道岔、编组、侧线、铺轨图）解释这份架构说明中的四个边界，
全部用浏览器内的确定性规则演示。

## 教学主张

这份文档读起来像一份模块清单，本教程把它收成一条线索：

> 一个终端工具之所以长成应用框架，是因为四处在画边界：进程、渲染、控制、构建。

| 边界 | 文档里的落点 | 换来了什么 |
| --- | --- | --- |
| 进程 | Bun 单二进制 | 装配前移到发布流水线 |
| 渲染 | React + Ink | 终端成为组件树，而不是 printf |
| 控制 | QueryEngine | 六件回合级状态由同一个循环持有 |
| 构建 | `feature()` 死代码消除 | 未发布的功能不在产物里 |

另外两处协议——工具四件套与 AppState 的订阅关系——决定了"能力怎么接进来"和"状态怎么传出去"。

## 演示修订

按 [新芽幻灯片指南](https://grokcv.site/sprouts/guide/) 与
[张雨函的分享建议](https://grokcv.site/sprouts/yuhan/) 组织：

- **一页一观点**：13 页全部用结论式标题，副标题是一个问题；操作步骤、出处与边界放进讲稿。
- **字号与栅格**：正文 30px、局部标题 36px、焦点数字 46px（1600×900 固定画布，约合 22.5pt；
  全屏播放按视口整体放大）；字号只有三档，标题、页脚、章节标记位置全篇统一。
- **配色克制**：白底 + 蓝灰主色，语义色只有三种——蓝=当前/指导、绿=通过、红=风险，
  橙色只标"用户可调的强调量"；没有渐变背景与高饱和荧光色。
- **开篇信息完整**：第二页写全仓库、路径、更新日期、收藏数、许可状态与篇幅，并明确区分
  "文档陈述 / 代码可验证 / 本教程模型"三层。
- **图表先结论**：六站管线每站写出"坏了会怎样"，证据页用三档强度替代模糊转述，
  迁移页每条都给出前提、风险与最小验证。
- **动画节制**：只有封面两段同步演示，其余交互点击后立即反馈，没有旋转、飞入或循环动画。
- **批判性收尾**：固定有"证据强度"和"我的思考"两页，写明未纳入项与三条共同局限，
  并把"哪些能搬"拆成三堆而不是给一句口号。
- **时间分配**：建议 15–17 分钟；讲稿逐页给出建议时长、操作顺序、停顿点与过渡句。
