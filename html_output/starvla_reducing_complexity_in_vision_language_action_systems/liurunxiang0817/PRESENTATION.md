# StarVLA-α：4 分钟汇报导演稿

## 0:00–0:25｜封面：一句话讲清论文

“当前 VLA 系统在架构、预训练、机器人接口和基准工程上越来越复杂，也越来越难判断哪些设计真正有效。StarVLA-α 的核心结论是：依托强大的 VLM 主干，配合简单连续 MLP 与最小数据处理，无需额外架构复杂度或重度工程技巧，也能取得强劲性能。”

## 0:25–0:50｜§1 引言：为什么需要 StarVLA-α

“引言把问题归纳为三类异质性：数据和机器人不同、建模训练不同、评测实践不同。因此作者提出三项贡献：建立极简强基线，受控重评常见实践，再用单一 Generalist 做一体化评估。”

操作：依次点开“三类异质性”和“三项贡献”。

## 0:50–1:20｜§2 极简基线：简单但不弱

“架构只有一条主线：RGB 和指令进入 Qwen3-VL，动作 token 的隐藏状态通过简单 MLP 输出连续动作块。Table 1 说明它并不弱：LIBERO 98.8、WidowX 64.6、Google VM 76.0、RoboCasa 53.8，均高于这里列出的代表方法。”

操作：点击 Qwen3-VL 与 MLP；结果图切一次 RoboCasa。

## 1:20–1:55｜§3 动作头：连续预测是关键

“作者固定 VLM、数据和训练，只替换四种动作头。四个基准共同说明两点：第一，连续动作预测对高性能至关重要，始终优于离散 token 方法；第二，当 VLM 足够强大时，MLP、GR00T-style 和 π-style 这几种连续动作头的具体选型影响有限。”

操作：动作头先切 GR00T-style，再在 Table 2 切 WidowX 与 RoboCasa。

## 1:55–2:25｜§4 预训练：关键是对齐，不是越多越好

“RoboTwin 的 Clean 50×50 条件下，高度匹配的 RoboTwin-Rand 预训练把 50.3 提到 79.7；但目标换成 RoboCasa 后，额外预训练反而可能损害泛化。强 VLM 基线已经扎实，动作专属预训练是一把双刃剑，必须谨慎使用。”

操作：RoboTwin 选 Clean 50×50 和 RoboTwin-Rand；再切 RoboCasa。

## 2:25–2:50｜§5 数据工程：主要是低数据工具

“这里的 24×10、24×100、24×1000，表示 24 个任务、每个任务分别使用 10、100、1000 条演示。任务专属数据有限时，数据工程可带来适度收益；数据充足后，五种设计集中在 52.6 到 55.5，影响基本可以忽略。”

操作：滑块从 24×10 拉到 24×1000。

## 2:50–3:20｜§6 怎样评估真正的泛化

“更有效的范式是：用单一 Generalist 联合训练多基准，再统一评测多任务和多机器人形态。它证明一个模型可以保持竞争力，复杂专家式跨形态设计也未必必要。支撑这种泛化还有两个关键条件：2B 到 4B 提升明显，4B 到 8B 已不足 1%；批大小越大表现越好，512 时 RoboCasa 和 RoboTwin-Clean 已达到 57.3 和 57.2。”

操作：Specialist 与 Generalist 切换；再展示“模型大小”和“批大小”。

## 3:20–3:40｜§7 实机：优势明显，问题仍未解决

“ARX5 的 11 个任务上，StarVLA-α 成功率 33.6、进度分 54.5；π₀.₅ 只有 12.7 和 27.6。极简框架在真实机器人上仍有竞争力，但 33.6% 也说明可靠部署远未解决。”

操作：成功率切到进度分。

## 3:40–4:00｜§8 结论

“所以论文的最终结论是：强 VLM、简单 MLP 动作头与最小数据处理，已经足以在多基准和真实机器人上取得强劲结果；复杂动作头、重度数据工程和任务专属预训练，并非构建通用机器人智能体的严格必要条件。StarVLA-α 的价值，是提供一个简洁、可复现、可推广的研究起点。”

## 10 秒备用总结

“StarVLA-α 用强 VLM 加简单连续 MLP 建立极简强基线，并证明复杂动作头、专属预训练和数据工程都不是普遍必要；单一 Generalist 与实机结果进一步说明这种简洁设计具有竞争力。”
