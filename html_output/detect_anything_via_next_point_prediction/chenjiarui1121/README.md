# 用下一个点预测检测任意目标：Rex-Omni 交互式教程

论文：*Detect Anything via Next Point Prediction*（Qing Jiang 等，IDEA Research，arXiv 2510.12798v1，2025）
论文链接：https://arxiv.org/abs/2510.12798 （CC BY 4.0）

由 **paper-skill 1.5.0**（ReductTech/PaperSkill，commit `80cbbed`）生成的完整 React + TypeScript + Vite 网页项目，PPT 式固定 1600×900 幻灯片，共 20 页（封面 + 8 章 19 页）。

## 本地运行

```bash
npm install
npm run dev       # 开发预览 http://localhost:5173
npm run build     # 产出 dist/ 静态站点
npm run preview   # 预览构建结果
```

顶部翻页，左侧缩略图选页，“讲稿”打开每页的出处与类比边界说明，“放映”进入全屏。手机保持原排版，可双指缩放、拖动。

## 教学结构

按读者会问的问题推进：先让读者亲手当一次大模型去框鸟，自己造出漏检、重复和框偏；再讲论文给出的两个原因（坐标逐位写、训练时总有人替它写前文），对应的两个改法（坐标格子词元、GRPO 自己写完再打分），实验证据，最后是效果与代价。术语第一次出现就解释并给论文原词。

| 章 | 页面标题 | 读者的操作 |
| --- | --- | --- |
| 封面 | Detect Anything via Next Point Prediction | 对照旧方法与本文方法 |
| 让大模型框鸟会出什么错？ | 一个框四个数，框得好不好看 IoU | 拖动蓝色预测框或右下角手柄，方向键也可移动 |
|  | 检测器框得准不懂话，大模型懂话框不准 | 点 ① 到 ④ 或“下一步”，看两类模型的框和计数怎样变化 |
|  | 你来当大模型：逐个画框，自己决定何时停 | 在照片上拖动画框；点“写结束标记”；可擦掉或重来 |
| 为什么框会偏？ | 大模型一次只写一个字，坐标也得一位位写 | 点“预测下一个 token”，框写完后选择继续或结束 |
|  | 原因一：错一格和错几百格，扣的分一样 | 点三个典型情形，或用 ±1、±50 调整四个坐标 |
| 为什么会漏、会重复？ | 原因二：训练时总有人替它写好前文 | 点“两边各写下一个框”，比较两侧的框数与反馈 |
| 改法一：坐标变格子 | 改法一：把坐标变成 1000 个格子 | 拖动橙色点；切换图像宽度，比较三种写法的词元数 |
|  | 点、框、多边形，统一成“短语 + 坐标” | 点左侧任务卡，观察照片上的几何与下方词元序列 |
|  | 一个框只要 4 个词元，写完再决定停不停 | 点“写下一个词元”，或“写完这个框”“连续写” |
| 格子从哪学来？ | 这些格子从哪学：约 2200 万张图的自动标注 | 拖动橙色点；切换形容词过滤开关 |
| 改法二：自己写完再打分 | 两步训练：先照着答案学，再自己写完打分 | 点两个阶段，对比前文来源、监督信号、数据量和算力 |
|  | 打分规则：每只鸟找最像的框，算重叠 | 拖动或缩放蓝框；添加重复框、换成大框、切换类别、删除 |
|  | 同一张图写 8 份答案，比平均好的被加强 | 点“再采样一组”“按优势更新一步”；点某根柱子查看该回答 |
| 真的是这两个原因吗？ | 重复框和大框，GRPO 后几乎消失了 | 点上方按钮，在原始输出与清理后输出之间切换 |
|  | 坐标只准了一点点，主要是更容易采到好答案 | 切换 COCO、LVIS、Dense200，比较四根柱子 |
|  | 四条证据，哪些站得住 | 点左侧四条论证，查看现象、假设、实验、数据和结论 |
| 效果、代价与回顾 | 宽松标准下追上检测器，严格标准下仍落后 | 切换数据集和 IoU 阈值，查看柱状图排序与结论 |
|  | 代价：框越多越慢，部分任务仍不如专用模型 | 拖动“预测框数量”滑块，观察词元数与估计时间 |
|  | 回顾：一个框从格子到奖励 | 拖动或缩放蓝框；切换“多写一个重复框” |

## 目录结构

| ---- | ---- |
| `src/data/tutorial.ts` | 章节、页面、讲稿（由组装器生成） |
