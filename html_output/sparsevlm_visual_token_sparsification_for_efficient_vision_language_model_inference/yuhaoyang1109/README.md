# SparseVLM 交互式中文精读（PaperSkill · 长滚动版 v1.1）

论文：*SparseVLM: Visual Token Sparsification for Efficient Vision-Language Model Inference*（ICML 2025，PMLR 267: 74840–74857；Yuan Zhang\*, Chun-Kai Fan\*, Junpeng Ma\*, Wenzhao Zheng, Tao Huang, Kuan Cheng, Denis Gudovskiy, Tomoyuki Okuno, Yohei Nakata, Kurt Keutzer, Shanghang Zhang）。

- 正式记录：https://proceedings.mlr.press/v267/zhang25s.html
- 代码固定到 `v1.5` 分支 `734d900`（该提交只改 README，代码最后一次改动 `535f8ba`，2025-03-03）；视频实验看 `video` 分支 `f05b898`。不用仓库默认的 `main` 分支（现为 SparseVLM+）。

## 运行

```bash
npm install
npm run dev       # 开发预览
npm run build     # 产出 dist/
node tools/make-outlines.cjs   # 由 src/data/tutorial.ts 重新生成 outlines.json
```

调试参数：

- `?all=1`：一次展开全部章节。
- `?motion=reduce`：与系统“减少动态效果”走同一条代码路径——画布直接画终态、封面不播放、时间轴停在终态；CSS 过渡关闭；6.1 的自动播放仍按所选速度走步（每一步是内容切换）。
- `?tl=0.5`：1.1、4.1、7.1 的时间轴定格在该进度、不自动播放，用于截取各阶段画面。
- `#chap-N` / `#closing` / `#glossary` / `#sources` / `#videos`：打开时直接定位（`#m-6.1` 这类模块锚点在 `?all=1` 下也可用）。

## 版式

参照 VTW v7.3 长滚动版（外壳）与 DivPrune v9.5（响应式修复）：

- 左侧固定章节栏 288px；窗口不足 1280px 时收为抽屉（顶栏“章节”按钮打开；点遮罩、按 Esc、点章节或拉宽到 1280 以上关闭）。
- 主区一列白色卡片（章卡最宽 1064px），正文 15–17px、章标题 26px、模块标题 17px，浅色光晕背景；外壳样式 `src/styles/v9.css` 取自参照页，未改。
- 封面：英文标题渐变字、中文标题、作者、单位、会议、摘要与关键词；原模型 / SparseVLM 两座 32 层 token 塔画在同一张画布里、共用一个时钟（进入视口播放一次后停在结果，可重播）；四个关键数字（带口径标记）；三条阅读路线；读前须知；“开始学习 §1”。
- 逐章展开：每章末尾“继续 §N+1”；侧栏或章内进度条可跳到任一章（展开到该章为止）。跳转后先对齐一次，主区尺寸仍在变化时跟着重新对齐（连续 300ms 不变或满 3 秒停止），读者滚动、按键或点击立即停止，对齐用 `behavior: 'instant'`。
- 每章栏目顺序：本节问题 → 类比（只在 §3、§7，附类比边界）→ 交互模块 → 洞察 → 公式（符号可悬停 / 聚焦 / 点按）→ 符号与推导 → 核对 → 关键数字 → 要点 → 常见误区 → 深入阅读（折叠）。`src/sv/content.ts` 的 `show` 指定每章显示哪些栏目。
- 收束：结论分级（交互模块 + 三栏完整分级，每条写依据）、复述五问、术语表（24 条，每条有“直觉”和“在本文中的作用”）、来源与证据边界（含配色图例）。
- 末尾“延伸学习 · B 站视频”：4 张外链卡片，封面随构建打包。

## 内容口径

四种标记，每个数字都能归到一类：**论文实测**（ICML 正式版正文、表、图；引用 arXiv 时写版本号）、**代码事实**（固定提交，链接带行号）、**公式外推**（本页按论文公式或代码口径计算 / 反推）、**教学示意**（示意数据与场景）。示意动画上不放看似精确的读数。

主要核对结论（详见各章“核对”与 §10）：

1. 图像版代码没有 Eq. (7) 的秩策略：第 2、6、15 层按写死的配额 topk；秩策略只在 `video` 分支（保留 rank(P) 个，只剪第 1 层）。`video` 分支调用该函数时少传一个参数（静态阅读，未运行）。
2. 表 1 的“保留 192 / 128 / 64 个”在代码里是 32 层“处理后”视觉 token 数的平均（192 档 576 → 309 → 204 → 113，平均 192.0）；按进入每层计算的数目平均是 206.5 / 145.4 / 82.3（64 档精确值 82.25，四舍五入）。
3. 论文与代码不一致：归簇（余弦 vs 欧氏）、合并（求和 vs 平均）、FlashAttention（附录 B 特制 V vs 剪枝层显式算完整注意力）、FLOPs 计数式（6ND² + 2N²D vs 4nd² + 2n²d + 3ndm）。按附录 B 字面推导，方向与 Eq. (3) 相反。
4. FLOPs 复算：按代码计数式、假设图像之外 118 个 token，三档 2.13 / 1.73 / 1.31 T（表 1：2.14 / 1.72 / 1.30）；“32 层每层都 R 个”得 2.03 / 1.61 / 1.19 T，与 ToMe 的 2.05 / 1.62 / 1.19 接近。
5. 正文与表格的出入：表 4 的回收提升（GQA +0.8、POPE +2.6）与正文“TextVQA 1.2%、POPE 7.2%”不符；“CUDA 时间降 43.1%”按表为 42.4%；结论“37.0% / 77.8% / 97%”混用了 192 与 128 两档；PDrop 128 档 MMB 百分比与原始分数对不上（94.6% vs 95.4%）。
6. 版本：VisionZip 表 1 的“SparseVLM(2024.10)”与 arXiv v1 是早期版本数字，与正式版并排展示、不混算。
7. KV Cache：论文 302.4 → 100.8 MB 相当于按“每层 192 个”计算；按代码逐层保留数，视觉 KV 约省 64%。
8. 计时范围：论文附录 F 描述的 CUDA 计时包含图像编码等环节；固定提交的计时（`modelling_sparse_llama.py` 第 214、366 行）只包围解码器循环，未覆盖视觉编码和评分员选择。两者与表 1 结果的具体对应关系尚未确认。
