# ACT 2 · Rank 配额室

本轮新增 ACT 2，接通 ACT 1 的下一章入口。ACT 3–9 仍为方案，不提前展示 AdaLoRA 完整算法。

## 五个教学检查

| 检查 | 本章的具体设计 |
| --- | --- |
| 用户会产生什么问题？ | 想给一个位置更多更新容量，额外的 Rank 从哪里来？交换之后，是否就能说模型更好了？ |
| 用户做出了什么主动判断？ | 预测扩容的代价；选择转出和转入位置；实际交换通道；对照初始配额；辨别直接观察到的是容量还是准确率；最后修正分配认识。 |
| 用户得到了什么论文证据？ | 上传 PDF 第 2 页 Sections 1–2、Eq. 1–2 的 LoRA 因子结构说明；回看 Figure 1 的同预算位置对照与实验条件。机制说明和实验观察分别标注。 |
| 用户最终理解了什么变量关系？ | Rank 控制低秩更新的容量上限。每个通道需要两侧参数。同尺寸矩阵下，总 Rank 守恒对应两因子参数总量守恒；各处份额可以不同。一处扩容需要别处让出预算，性能收益仍需验证。 |
| 页面是否误把教学模拟当成真实实验？ | 四处 64×64、总 Rank 12、1,536 个因子参数是教学设定。交换不产生准确率、训练日志或“最优”评分。Figure 1 仅回看原结论，不能为玩家配置打分。 |

## 已实现的主线

接管配额 → 预测 → 选择来源和目标、交换 → 对照初始与当前配额 → 辨认容量变化 → 揭示论文机制 → 修正结论 → 点亮节点。

错误预测照常进入主线；错误观察或绝对化结论先获得解释，再重新判断。每个部分给出通俗目的和过渡句。公式仅放在可展开的技术解释中，并紧邻直觉描述。

## 操作和边界

- 四个示例位置 A–D，各自初始 Rank 3、范围 0–8，合计 12。每条通道需要 64+64=128 个因子参数，合计 1,536。
- 每次只让指定来源减 1、指定目标加 1。其他位置不变。来源空、目标满、同一位置不能提交，并提供原因。
- 来源、目标、当前 Rank、完整交换记录、首次预测、证据阅读与修正判断独立保存。
- 恢复平均配额只恢复份额，保留已有交换记录；“重置本章”才重新开放预测与所有交互，并归档之前的体验。
- 重置 ACT 2 不改动 ACT 0/1，历史查看和导出包含三章。
- Rank 0 在这个教学配置中表示不分配更新支路，原权重仍参与计算。没有展示或混用下一章的贡献掩蔽机制。
- 同 Rank 在不同尺寸矩阵上的参数成本可以不同。这里固定同尺寸只是为了看清取舍。
- 概念蓝图中的机械臂只随一次有效交换移动；开启减弱动画时直接更新结果。

本章按用户授权单独开发，验收后停止在 ACT 2，等待评阅。

## 实际验证记录

- TypeScript 与生产构建通过；ACT 0、ACT 1 的已有逻辑检查通过。
- ACT 2 验证了 5,000 次交换尝试：总 Rank 12、因子参数 1,536 恒定，只有指定两个位置改变，所有值都在 0–8 内。
- 验证预测保留、学习门槛、空来源/满目标/同位置拦截、平均恢复不丢交换记录、保存数据校验和重置归档隔离。
- 独立预览实际完成主线，使用错误初始预测仍能继续；将容量变化当作准确率提升、将手动交换当作自动分配时，得到纠错且不能直接完成。
- 使用 Enter 完成交换；刷新后恢复配额、来源、目标与章节位置；完成后 ACT 2 节点点亮。
- 重置后恢复 3/3/3/3、零次交换和未读证据，历史中仍保留重置前的已完成体验。
- 桌面 1440×1000 与手机 320×740 检查无页面横向溢出。截图见 act2-desktop.png、act2-mobile.png。
