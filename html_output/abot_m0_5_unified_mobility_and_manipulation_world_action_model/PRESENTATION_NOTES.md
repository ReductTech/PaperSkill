# ABot-M0.5 四分钟汇报讲稿

## Screen 01 · 问题（约 35 秒）

先别急着看模型结构。移动操作真正困难的地方，是三个接口没有对齐：视频预测很粗，抓取控制却很细；底盘和机械臂动力学不同；训练时看真实未来，部署时只能看模型自己预测的未来。作者的核心判断是：问题不只是容量不够，而是时间、动作空间和训练条件都存在结构错配。

**过渡：** 这三个问题看似不同，其实都是接口没对齐。因此 ABot-M0.5 没有从视频硬预测动作，而是在中间重新设计了一条 z→m→a 的因果链。

## Screen 02 · 总体思路（约 40 秒）

这一页先用机器人打羽毛球看全局。高速来球只给我们少量视觉状态，但击球需要连续、精细的动作，因此第一步要用 latent action m 把视觉时间粒度接到控制时间粒度。为了接球，脚要快速追到击球位，手要精确对准并挥拍；两套动力学应该分开学，却又必须共享同一条球路和回球目标。最后，风和触球位置会让实际轨迹偏离理想轨迹，部署时动作模型面对的是自己预测出来的未来，因此训练条件也要向这种 Self-Dreamed Future 对齐。这里风与触球偏差只是帮助理解“未来会偏离标准轨迹”，Dream Forcing 的技术本质不是预知所有扰动，而是让动作模型学会从自己生成的未来继续行动。

**过渡：** 现在我们已经得到最终动作 a。下一问是：机器人的“手”和“脚”，真的应该由同一套动作模型一起学吗？

## Screen 03 · Latent Action（约 40 秒）

第一个创新解决的是时间粒度问题。大家可以把它想成横版游戏跳过一个坑：假设我只给你两张画面，一张是角色站在左边，另一张是他已经到了右边。我们当然知道未来结果，但真正操作时，还要知道什么时候起跳、怎样越过、什么时候落地。世界模型的视频预测也类似，它擅长描述未来状态，但机器人需要的是更细粒度控制。因此论文在中间加入 latent action m，从局部视觉状态变化中抽出 frame-level 的运动表示，再进一步生成真实 action。所以 z 看未来，m 看变化，a 才真正执行。

每讲完一个关键状态，再点击一次主按钮推进：只看未来、直接尝试、引入 m、展开控制、完成跳跃、映射机器人、查看消融。最后可补一句：游戏中的 motion token 只是概念类比，m 不是显式轨迹、额外视频帧或最终控制命令。论文 Table 7 在 RoboTwin 2.0（Clean）上的 latent-action 消融由 87.60 提升到 94.00。

**过渡：** m 解决了视频和控制的时间尺度，但机器人最终还要同时控制底盘与机械臂，这又带来第二种错配。

## Screen 04 · Dual-Level MoT（约 40 秒）

第二个创新解决动作空间错配。可以把机器人想成哪吒：风火轮负责移动，火尖枪负责精细操作。如果两者学同一套招式，低频平滑的移动和高频局部的操作会互相干扰；如果各打各的，又不知道对方把位置和目标改变成了什么。论文的办法是先让两者通过 joint attention 一起看同一张“战场地图”，再由各自的 Expert 专门决定怎么做。映射回机器人，就是底盘和机械臂分开学习，但共享任务与场景信息——Attention 负责商量，Experts 负责各干各的。

如评委追问 Dual-Level：第一层在 Video、Latent Action、Action 三种模态间保留各自表示身份并共享注意力；第二层在 Action 内部再把 Mobility 和 Manipulation 分到独立 FFN 与 prediction head。论文在 selected RoboCasa365 Composite-Seen subset 的消融由 0.34 提升到 0.48。

**过渡：** 到这里模型已经解决“怎么看运动”和“怎么拆动作”，但还有最后一个问题：训练与部署看到的未来根本不是同一个分布。

## Screen 05 · Dream Forcing（约 50 秒）

这一页每次点击只落一步棋或切换一个关键局面。先逐步跟着高手棋谱落子：每一步都有人摆好标准局面，所以下一步当然容易。再点“真正上场”，模型只偏了一格，当前棋盘就不再是棋谱上的那一页——训练看的是标准棋局，部署面对的是自己刚走出的棋局。Dream Forcing 先生成自己的未来局面，再直接从这个不完美局面学习动作；它不是强化学习 self-play，也不保证永不犯错，而是让动作模型见过部署时真正会遇到的条件。相同 warm start 下，继续 Teacher Forcing 5k 步为 66.78%，Dream Forcing 5k 步达到 70.56%。

**过渡：** 现在回头看，三个创新并不是三块孤立技巧，而是在同一条因果链上修复三个接口。

## Screen 06 · Takeaway（约 25 秒）

点击“开始收束”，每讲完一把钥匙再点“下一把钥匙”。前面三个创新看起来分散，其实都在开同一把锁：对齐。第一把钥匙把未来视频和真实控制的时间粒度对齐；第二把钥匙让移动与操作按不同动力学专业化，同时共享任务语义；第三把钥匙让训练时看到的条件对齐部署时真正面对的条件。之后依次点击“打开对齐之锁”“点亮因果链”“查看最终总结”。三次对齐修复“世界预测—运动抽象—真实控制—部署条件”这条因果链，所以 ABot-M0.5 并不是简单堆出三个模块，而是在同一条链上修正三种结构性错配。

最后只强调一句：这篇论文的核心不是更大的模型，而是更少的错配。
