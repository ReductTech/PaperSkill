# 功能六：修改已有的网页

**定位：在已有版本的基础上继续修改。Agent 负责把网页复制成新版本目录并自动生成 `paper.json`（含版本溯源信息），复制完成后由使用者自行修改网页内容。**

## 1. 需要的信息

只询问缺失项：

- 要修改的网页相对路径，形如 `html_output/<论文名>/<版本名>`（例如 `html_output/attention_is_all_you_need/tianaopang0913`）。使用者也可以只给论文名、版本名或仓库链接，Agent 自行定位到具体版本；
- 使用者的公开展示名；
- 使用者的 GitHub 用户名；
- 姓名拼音小写（展示名是中文时必须提供，例如 `lilei`），用于生成新版本目录名。

## 2. 执行步骤

1. 确认环境已就绪（功能 1 已完成，仓库已克隆或更新）；
2. 在仓库根目录运行（展示名是中文时必须传 `--pinyin`）：

   ```powershell
   npm run modify -- <论文名>/<版本名> --participant "展示名" --github "用户名" --pinyin "拼音"
   ```

3. 命令自动完成两件事：把该版本复制为同一篇论文下的新版本目录 `html_output/<论文名>/<姓名拼音小写+MMDD>/`（同一天重复执行自动追加 `_2`），并生成新的 `paper.json`。复制会跳过 `node_modules/`、`dist/`、`.npm-cache/` 与旧 `paper.json`——不要手工复制整个目录或依赖；
4. 如命令报错（版本已存在、找不到该版本等），按提示修正参数后重试，不要绕过命令手工创建目录；
5. 命令运行结果中的新目录路径、本版作者和溯源链必须如实转达使用者。

## 3. 必须告诉使用者的三件事

1. **可以开始修改** —— 给出新目录路径，说明直接修改该目录里的网页源码即可；
2. **已写入版本溯源信息** —— 新 `paper.json` 增加了 `ancestors` 字段，按时间顺序记录这份网页此前每一位作者的公开展示名与 GitHub 用户名，第一位是原创，第二位是二创，以此类推。
3. **后续怎么走** —— 修改完成后回到菜单，依次选择功能 4（创建分支，导入主仓库）、功能 5（准备提交 PR）。

## 4. 注意

- 不要删除或覆盖原有版本目录，同一篇论文的每个版本都独立保留；
- 多人接力修改时无需手工维护链条：继续在新的版本上重复执行本功能，`ancestors` 会自动变成「元老 → 第二位 → 第三位……」的完整顺序；
- 分支由功能 4 创建，本功能只在工作区里复制目录，未提交的改动会随工作区带到新分支；
- 本功能不校验、不构建，网页内容准确性由使用者人工负责。
