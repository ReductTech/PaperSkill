# 功能三：给出人工修改建议

**定位：本功能只产出「修改建议」，不要求 Agent 实际修改项目代码。**

Agent 可根据原论文和实际测试，向参与者列出候选问题，每项包含：

- 初版问题和位置；
- 论文原文、公式、实验数据或测试结果依据；
- 建议修改内容；
- 修改原因和预期效果；
- 所属类别。

参与者必须理解并确认至少三项实质性修改，且覆盖两个及以上类别。Agent 应确保参与者**能够解释每项修改的依据**（问题出在哪、对照论文哪句话、为什么这么改）。

> **本功能不强制 Agent 在此处动手改代码。** 后续的实质性修改，大概率由参与者拿到建议后，在其他 Agent 或直接编辑 `html_output/<slug>_<source>/` 源码完成，甚至跨多次会话。Agent 在功能三里**无需、也不应冒充人工修改**——人工修改必须由参与者本人理解并落实。

完成后生成一页以内的修改说明草稿，每项写明问题、修改内容、原因和验证结果（「验证结果」可标注为「待参与者在后续编辑中落实，仅供参考」）。该文件保存在仓库外，不放入 `html_output/`。

> **交接提示：** 导入环节（功能四）会**直接执行导入与校验，不读取也不核对本草稿**，因此草稿不必交给导入流程，只要参与者自己留好即可。
