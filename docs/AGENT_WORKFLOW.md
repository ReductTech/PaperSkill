# Agent 菜单模式执行规范

本文件供 Agent 读取和执行。使用者从仓库根 `README.md` 复制指令发送给 Agent 后，Agent **不要一次性连续执行全部流程**，而是先向使用者展示功能菜单，由使用者选择要执行的功能，再读取 `agent-workflow/` 下对应的说明文件执行。

## 0. 智能体入口：展示菜单

收到使用者的消息后，按以下顺序处理：

1. 读取本文件与 `docs/agent-workflow/` 目录；
2. 向使用者展示如下菜单；
3. 根据使用者选择，读取 `docs/agent-workflow/<对应文件>` 并严格执行；
4. 单个功能执行完成后，需要再次展示菜单，等待使用者下一步选择。

```text
请选择要执行的功能（建议按顺序执行）：
1. 自动准备环境 —— 检查 Node/npm/Git/GitHub，克隆或更新仓库，安装 paper-skill
2. 调用 paper-skill 生成网页 —— 生成 React+TS 教程并预览（npm install / npm run build / npm run dev）
3. 人工校验网页准确性 —— 提醒使用者重点检查网页是否正确表述所选论文的内容，并对照原论文核对事实、公式、模型结构、实验数据、结论和局限
4. 导入主仓库 —— 将最终修改后的项目导入 html_output 并完成仓库校验
5. 准备提交 PR —— Agent 自动检查提交格式和构建，提供最终网页预览并由使用者确认显示后，准备 PR 内容、推送个人分支并创建 Pull Request
```

功能 2 完成时，Agent 必须在生成结果、项目路径、构建状态和预览方式之后再次完整显示以上五项菜单，并暂停等待选择；不得只报告生成完成，也不得自动进入功能 3。

## 1. 上下文纪律（重要）

Agent **只读取 `README.md` 与 `docs/` 下的文档**来理解「该做什么」，其余内容一律视为黑盒，通过运行命令间接使用，**不要将代码源码读入上下文**：

- `paper-skill/`：已安装为独立 skill，对应功能直接「调用」；
- `scripts/`（setup / import-paper / validate 等）：直接运行，只看命令输出与报错，不读源码；
- `html_output/`、`portal/`、`assets/`：仅为导入/校验/构建产物目录，不读源码；
- `package.json` 内部：通过 `npm run xxx` 间接使用，不读。

> 唯一例外：某条命令运行失败时，才**按需且仅读取**那一个出错的脚本源码用于排查；定位后继续，不扩大读取范围。

## 2. 执行原则

- 在同一个任务中连续推进所选功能，不把可以自动执行的命令交还给使用者；
- 发现已有本地修改时先保留并说明，不得重置、覆盖或删除无关内容；
- 不直接向 `main` 推送，不替使用者确认论文事实、内容准确性或网页预览结果；
- 密码、令牌、私钥和个人隐私不得写入仓库；
- 每个功能执行失败时先定位并修复，只有确实需要账号授权、系统权限或使用者判断时才暂停。

## 3. 必要信息

尽量从当前任务、论文和 Git 配置中自动获得以下信息，只询问缺失项：

- 论文文件、LaTeX、正文或有效链接；
- 使用者姓名或公开展示名，以及用于目录命名的姓名拼音小写（例如 `liming`）；
- GitHub 用户名；
- 论文目录标识 `paperName`（论文全称小写加下划线，例如 `attention_is_all_you_need`）；
- 版本目录标识 `version`（姓名拼音小写加修改日期 MMDD，例如 `liming0903`）；

`paperName` 为论文全称小写加下划线连接，`version` 为姓名拼音小写加修改日期。教程最终位于 `html_output/<paperName>/<version>/`，同一篇论文的多个版本并列保留。Agent 可以给出建议值，但应让使用者确认论文和身份信息。

> 菜单模式提示：各功能可能在不同会话中分别调用。建议将已收集的论文与身份信息（paperName、姓名拼音、公开展示名、GitHub 用户名、生成项目路径、已安装 skill 版本、版本目录标识）记录到本地状态文件，跨功能调用时复用，避免重复询问。不得提交到仓库。
