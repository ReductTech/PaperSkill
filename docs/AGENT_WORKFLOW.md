# Agent 菜单模式执行规范

本文件供 Agent 读取和执行。参与者从仓库根 `README.md` 复制指令发送给 Agent 后，Agent **不要一次性连续执行全部流程**，而是先向参与者展示功能菜单，由参与者选择要执行的功能，再读取 `agent-workflow/` 下对应的说明文件执行。

## 0. 智能体入口：展示菜单

收到参与者的消息后，按以下顺序处理：

1. 读取本文件与 `docs/agent-workflow/` 目录；
2. 向参与者展示如下菜单，并说明每个功能对应的流程阶段；
3. 根据参与者选择，读取 `docs/agent-workflow/<对应文件>` 并严格执行；
4. 单个功能执行完成后，可再次展示菜单，等待参与者下一步选择。

```text
请选择要执行的功能：
1. 自动准备环境 —— 检查 Node/npm/Git/GitHub，克隆或更新仓库，安装 paper-skill
2. 调用 paper-skill 生成网页 —— 生成 React+TS 教程并预览
3. 给出人工修改建议 —— 列出候选问题，协助确认≥3项实质修改
4. 导入主仓库 —— 将最终修改后的项目导入 html_output 并完成仓库校验
5. 准备提交 PR —— 准备 PR 内容并推送个人分支、创建 Pull Request
```

## 1. 上下文纪律（重要）

Agent **只读取 `README.md` 与 `docs/` 下的文档**来理解「该做什么」，其余内容一律视为黑盒，通过运行命令间接使用，**不要将代码源码读入上下文**：

- `paper-skill/`：已安装为独立 skill，功能 2 直接「调用」它，**不读源码**；
- `scripts/`（setup / import-paper / validate 等）：用 Bash **直接运行**，只看命令输出与报错，**不读源码**；
- `html_output/`、`portal/`、`assets/`：仅为导入/校验/构建产物目录，**不读**；
- `package.json` 内部：通过 `npm run xxx` 间接使用，**不读**。

> 唯一例外：某条命令运行失败时，才**按需且仅读取**那一个出错的脚本源码用于排查；定位后继续，不扩大读取范围。

## 2. 执行原则

- 在同一个任务中连续推进，不把可以自动执行的命令交还给参与者；
- 发现已有本地修改时先保留并说明，不得重置、覆盖或删除无关内容；
- 不直接向 `main` 推送，不替参与者确认论文事实或冒充人工修改；
- 密码、令牌、私钥、论文 PDF 和个人隐私不得写入仓库；
- 每个阶段失败时先定位并修复，只有确实需要账号授权、系统权限或参与者判断时才暂停。

## 3. 必要信息

尽量从当前任务、论文和 Git 配置中自动获得以下信息，只询问缺失项：

- 论文 PDF、LaTeX、正文或有效链接；
- 参与者姓名或展示名；
- GitHub 用户名；
- 作品来源标识 `source`；
- 论文目录标识 `paperSlug`；
- 考核外部材料的提交入口（没有公布时只记录为待办）。

`paperSlug` 和 `source` 只能使用小写字母、数字和中间连字符。Agent 可以给出建议值，但应让参与者确认论文和身份信息。

> 菜单模式提示：各功能可能在不同会话中分别调用。建议将已收集的论文与身份信息（paperSlug、source、participant、github、生成项目路径、已安装 skill 版本）记录到本地状态文件，跨功能调用时复用，避免重复询问。状态文件不得提交到仓库。
